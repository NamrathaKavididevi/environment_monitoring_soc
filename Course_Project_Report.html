ABSTRACT

This Honours Course Based Project report documents the architectural design, synthesizable RTL integration, bare-metal RISC-V firmware development, and comprehensive UVM 1.2 functional verification of an RTL-Based Environmental Monitoring and Data-Logging System-on-Chip (SoC) engineered for autonomous, real-time sensing edge nodes. Built around the open-source Western Digital / CHIPS Alliance VeeR EL2 RV32IMC processor core with 32 KB Instruction Closely Coupled Memory (ICCM) and 64 KB Data Closely Coupled Memory (DCCM), the SoC bridges the critical gap between isolated academic peripheral demos and industrial-grade multi-peripheral sensor platforms.

The system architecture integrates a high-performance memory-mapped crossbar interconnect with round-robin arbitration, 64 KB of unified on-chip single-cycle SRAM, and six dedicated memory-mapped peripheral subsystems: an I2C Master Controller for periodic ambient temperature and humidity sensor acquisition; an Interval Timer IP establishing precision sampling intervals and time-stamping; an SPI Master Controller providing high-speed burst writes to external non-volatile Flash memory for durable logging; a PWM Generator modulating audible alarm tones upon sensor limit violations; a 32-bit bidirectional GPIO Controller driving visual warning LEDs and capturing emergency operator triggers; and a 115200-baud UART Controller delivering continuous live telemetry reports and diagnostic trace logs.

In addition, a standalone NIST FIPS-197 AES-128 Encryption Module was verified in its own dedicated subsystem environment to demonstrate tamper-proof cryptographic telemetry hardening without modifying the core SoC RTL footprint.

Comprehensive functional verification was achieved across a 23-test dual-sided verification matrix combining bare-metal C firmware (main.c, uart.c) executing on the core with a modular UVM 1.2 environment featuring six custom Verification IPs (UART, GPIO, Timer, SPI, I2C, and PWM). Cycle-accurate Synopsys Verdi and QuestaSim waveform analysis demonstrates deterministic sensor readouts, flawless crossbar arbitration, precise address decode trapping (DECERR), and a 100% clean regression signature (PASS_SIGNATURE = 0x900D).

1.2 Motivation and Problem Statement

Autonomous environmental sensing edge nodes deployed in industrial automation, cleanrooms, server racks, precision agriculture, and aerospace facilities require continuous, deterministic monitoring of ambient parameters such as temperature, relative humidity, air quality, and atmospheric pressure. Conventional architectures rely on off-the-shelf microcontrollers where software loops frequently block on slow serial peripherals (I2C, SPI, UART). Under anomalous spikes or emergency conditions, CPU latency in servicing interrupts can lead to delayed acoustic/visual alerting, lost telemetry records, or memory corruption.

Furthermore, academic VLSI projects frequently evaluate individual intellectual property (IP) cores in complete isolation using trivial Verilog testbenches. Real-world silicon, however, demands the integration of open-standard processor cores, multi-channel memory-mapped interconnect crossbars, tightly coupled memories, hardware error detection, and multi-agent Universal Verification Methodology (UVM 1.2) verification suites.

1.3 Literature Survey & Industrial Benchmark

Contemporary industrial edge-sensing architectures were surveyed to establish architectural benchmarks:

  • Microchip ATmega328P / SAMD21: 8-bit / 32-bit single-issue architectures with narrow peripheral bandwidth and software-polled I2C/SPI interfaces. Under heavy logging, core execution stalls by up to 65%, rendering them unsuitable for high-frequency telemetry.
  • STMicroelectronics STM32F4 / L4 Series: High-performance ARM Cortex-M4 architectures utilizing proprietary AHB/APB matrix interconnects. While computationally capable, proprietary licensing limits open-source hardware customization and silicon sovereignty.
  • Western Digital / CHIPS Alliance VeeR EL2: A 1-to-2-way superscalar, 4-stage pipeline 32-bit RISC-V processor core supporting the RV32IMC instruction set. VeeR EL2 features tightly integrated 32 KB ICCM and 64 KB DCCM, out-of-order retirement, dual instruction issue, and an integrated Programmable Interrupt Controller (PIC).

1.4 Proposed Architectural Innovations

To overcome conventional limitations, the proposed Environmental Monitoring SoC incorporates four major architectural innovations:

  1. Hardware-Decoupled Peripheral Acceleration: Dedicated synthesizable controllers for I2C, SPI, UART, Timer, GPIO, and PWM eliminate CPU polling overhead. Hardware FSMs autonomously orchestrate serial transfers.
  2. Deterministic Memory-Mapped Crossbar Interconnect: A high-performance interconnect matrix supporting round-robin arbitration, 32-bit address/data pipelines, and explicit address decode error trapping (DECERR) protecting memory integrity.
  3. Hardware-Accelerated Dual Alarming & Fail-Safe Logging: Multi-stage threshold comparators directly govern pulse-width-modulated (PWM) audio buzzers and GPIO status indicators while concurrently streaming telemetry packets over SPI Flash.
  4. Standalone Cryptographic Telemetry Hardening: An isolated NIST FIPS-197 AES-128 cryptographic engine was developed and verified in a dedicated verification environment to demonstrate payload encryption for secure telemetry links.

1.4 Proposed Architectural Innovations (Continued)

The architectural design specifically addresses real-time determinism and fault resilience through dedicated hardware blocks:

  • Hardware Sensor Ingest (I2C Master): Implements automated START/STOP generation, 7-bit addressing, and ACK/NACK verification to autonomously poll ambient temperature and humidity sensors without CPU bit-banging.

  • Non-Volatile Hardware Logging (SPI Master): Master-mode SPI peripheral driving high-speed serial clock generation (SCLK), shift registers, and chip-select control to commit timestamped records to external Flash memory.

  • Non-Blocking RISC-V Execution: The VeeR EL2 core operates out of dedicated 32 KB ICCM and 64 KB DCCM closely coupled memories, insulating core execution from bus traffic.

6.1 Verification Methodology & Strategy

Verifying an integrated System-on-Chip requires a dual-perspective verification methodology. Software execution alone cannot guarantee bus timing compliance, signal integrity, or external protocol adherence. Conversely, hardware testbenches cannot observe the internal execution context of firmware subroutines.

6.2 Dual-Perspective Verification Architecture (Internal vs. External)

The verification architecture establishes two complementary, synchronized validation lenses:

  • Internal Verification (C Firmware): Bare-metal firmware running natively on the VeeR EL2 processor core. It writes stimulus to peripheral registers, measures internal timing, executes algorithm logic, and signals test pass/fail via designated memory-mapped signatures (PASS_SIGNATURE = 0x900D).
